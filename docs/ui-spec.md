# UI 仕様

対象画面: Pebble Time 2 (emery)、200×228 px。背景は黒 (`#000000`)。
レイアウト定義は `src/embeddedjs/emery/layout.js`、variant の更新ロジックは
`src/embeddedjs/main.js` の `onClockChanged` にある。

## 画面レイアウト

```
(0,0)                                        (200,0)
┌──────────────────────────────────────────────┐
│ ┌────────┐┌────────┐          SEP  (月)      │  時: 60×90 ×2 (left:0/60, top:10)
│ │   H1   ││   H2   │          01   (日 2桁)  │  月: left:148, top:10
│ │        ││        │          MON  (曜日)    │  日: left:174/186, top:35
│ └────────┘└────────┘                         │  曜日: left:148, top:60
│ STEP          ┌────────┐┌────────┐           │  STEP ラベル: left:2, top:105
│ 01234         │   M1   ││   M2   │           │  歩数 5 桁: left:2+14n, top:130
│               │        ││        │           │  分: 60×90 ×2 (left:80/140, top:100)
│               └────────┘└────────┘           │
│ 29/21                                        │  気温 5 マス: left:2+14n, bottom:34
│            ▼ (インジケータ)                    │  indicator: left:5+時×8, bottom:28
```

時 (左上) と分 (右下) を対角に配置した非対称レイアウトが特徴。

## 表示要素と variant の対応

`onClockChanged` はコンテナの子 Content を先頭から順に辿り、variant を設定していく。
**layout.js 内の Content の並び順と main.js の更新順は 1:1 で対応しており、順序を崩すと表示が壊れる。**

### 差分更新によるバッテリー最適化

Piu は `content.variant` / `content.coordinates` への代入を、値が同じでも無条件に
invalidate + reflow するため、素朴に毎分全要素へ代入すると全 43 コンテンツが
再描画対象になる。これを避けるため:

- variant の更新は `setVariant()` ヘルパー経由で行い、**現在値と異なるときだけ代入**する。
  毎分実際に再描画されるのは値が変わった要素 (通常は分の 1〜2 桁と歩数の下位桁) のみ
- インジケータの `coordinates` は `lastIndicatorHour` と比較し、**時が変わったときだけ**移動する

| # | 要素 | Skin | variant の値 |
|---|---|---|---|
| 1–4 | 時刻 H1 H2 M1 M2 | `digitsSkin` | `designOffsets[i] + 数字` (後述) |
| 5 | 月 | `monthsSkin` | `getMonth()` (0–11) |
| 6–7 | 日 (十の位, 一の位) | `smallDigitsSkin` | 各桁の数字 |
| 8 | 曜日 | `daysSkin` | `getDay()` (0=日曜) |
| 9 | STEP ラベル | `labelsSkin` | 0 固定 |
| 10–14 | 歩数 5 桁 | `smallDigitsSkin` | 各桁の数字 (ゼロ埋め表示、上限 99999) |
| 15–16 | 最高気温 2 桁 | `smallRedDigitsSkin` (#FF5500) | 各桁の数字 |
| 17 | 区切り記号 | `smallDigitsSkin` | 10 固定 (small_digits.png の 11 マス目) |
| 18–19 | 最低気温 2 桁 | `smallBlueDigitsSkin` (#55AAFF) | 各桁の数字 |
| 20–43 | 天気ドット ×24 | `weatherSkin` | `WEATHER_CODES.charCodeAt(i) - 65` (0–25) |
| 44 | 時刻インジケータ | `indicatorSkin` | — (coordinates を `left: 5 + hours*8` に移動) |

## 数字デザインのランダム選択 (本プロジェクトの中核仕様)

時刻 4 桁は `large_digits_40.png` に収録された **4 種類のデザインセット** (各セット 0〜9 の
10 文字、計 40 variants) のいずれかで描画される。`designOffsets[i]` はセット先頭の
variant オフセット (0 / 10 / 20 / 30) を保持する。

### 選択ルール (`getRandomOffsetForDigit`)

1. **重み付きランダム**: `WEIGHTS = [0.43, 0.33, 0.23, 0.01]` — セット 0 が最も出やすく、
   セット 3 は約 1% のレア枠
2. **同一数字の重複禁止**: 4 桁の中に同じ数字が複数ある場合 (例: 11:15 の「1」)、
   それらが同じセットになることは禁止 (まったく同じ絵が並ぶのを防ぐ)。
   数字が異なる桁同士なら同じセットでもよい
3. 使用可能なセットが尽きた場合は先頭の未使用オフセット、それもなければ 0 にフォールバック

### 再抽選のタイミング

**値が変わった (繰り上がった) 桁だけ**を再抽選し、変わっていない桁のデザインは維持する。

| 条件 | 再抽選される桁 |
|---|---|
| 毎分 | M2 (分の一の位) |
| 分の一の位が 0 になったとき (10 分ごと) | M1 も |
| 毎時 0 分 | H2 も |
| 毎時 0 分 かつ 時の一の位が 0 (10 時, 20 時, 0 時) | H1 も |

再抽選時は対象桁のオフセットを一旦 `-1` にリセットしてから順に選び直すことで、
重複禁止ルールを対象桁同士にも適用している。

### 永続化と起動時検証

- 選択結果は `localStorage` の `DESIGN_OFFSETS` にカンマ区切りで保存され、
  watchface 再起動をまたいでもデザインが維持される。再抽選の結果が前回保存値と
  同一文字列になった場合は書き込みをスキップする (フラッシュ書き込み削減)
- 起動時に検証し、以下のいずれかに該当したら 4 桁全部を抽選し直す:
  - 要素数が 4 でない
  - 値が 0〜30 の範囲外、または 10 の倍数でない
  - 同じ数字の桁に同じオフセットが割り当てられている

### セット数の変更

セット数は `main.js` の `SET_COUNT` と `WEIGHTS`、および `large_digits_40.png` の
差し替えで変更できるが、**メモリ制約により 5 セット以上にするとクラッシュする**
([architecture.md](./architecture.md) 参照)。

## 24 時間天気ドットとインジケータ

- 画面最下部に 6×22 px のドット列を 24 個、8 px ピッチ (`left: 5 + col*8`) で配置
- 各列は縦に 3 マス (6×6 px、隙間 2 px) 並んでおり、**下段 1 マス = 弱、2 マス = 中、
  3 マス = 強**のように点灯数と色で天気と強度を表す (色定義は [assets.md](./assets.md))
- variant = その時刻の内部天気コード。`weatherSkin` は `variants: 6` (6 px ストライド) で
  `weather_dots.png` の列を横に選択する
- インジケータ (6×4 px の矢印) が `left: 5 + hours*8` に移動し、ドット列の真上から
  「現在の時刻」の列を指す

## 既知の制約・課題

- **天気ドットの色ずれ**: 内部天気コードは 0〜25 の 26 種だが、`weather_dots.png` は
  24 列しかない。さらに `misc/weather_dots.json5` の列定義の並び (index 9 = Light Rain など) は
  pkjs のマッピング (index 9 = Freezing Drizzle: Light) と index 9 以降で食い違っており、
  コード 9〜25 は意図と異なる色で描画される。コード 24, 25 はテクスチャ範囲外を参照する
- **氷点下の気温**: 気温の描画は `Math.idiv(temp, 10)` と `temp % 10` の単純分解のため、
  負の温度では variant が負になり正しく表示できない
- **歩数のゼロ埋め**: 歩数は常に 5 桁ゼロ埋めで表示され、先頭桁のブランク処理はない
